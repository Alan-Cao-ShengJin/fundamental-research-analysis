# Frozen drafts, fresh review and publication

This is the supported publication path for full company reports and their briefs. The earlier thesis challenge tests the analysis; this later review tests what the investor will actually read. Neither replaces the other. The author session uses the host's available authorized fresh-context capability to launch the readers/writer. In Claude Code this is the Agent tool; elsewhere use the supported equivalent. If unavailable, leave the dependent stage pending rather than fabricate review. The catalog and these scripts do not dispatch agents or verify reviewer identity.

## Pin rules before construction

At study creation run `research_rules.py pin STUDY`. This preserves actual production instructions, helpers, templates/assets and a Python/Node/dependency receipt in `evidence/rules-lock.json` and its archive. Tests/evaluation answers are excluded from production identity. A later shared edit does not redefine an existing study's standard.

After live rules change, `research_rules.py run STUDY release_check.py ABSOLUTE_STUDY_PATH` executes the preserved helper bytes in an isolated import root. The same runner accepts `publication_review.py` and its normal arguments, or a study-relative builder. The helper CLIs dispatch to preserved versions when necessary. Builders should obtain shared assets from `RESEARCH_SKILLS_ROOT` or the shared modules, not hardcode live workspace asset paths. Runtime receipts must match for new locks; original dependency versions were not captured by some historical archives, so that limitation remains explicit. This is versioned execution, not an OS sandbox or authentication of arbitrary source code.

Frozen old archives are inspected under their actual code without relabeling wrappers, modifying findings or resetting attempts. Current production requirements apply to new work. An explicit migration must preserve lineage and actual attempts; `--legacy` is still only historical integrity inspection.

## Fresh model challenge before writing

For a full initiation or material earnings/catalyst/model reconstruction, prepare the calculated model and stable pivotal source/construction records:

```text
python -B -X utf8 skills/report-layout/scripts/model_review.py prepare STUDY --spec model/spec.json --workbook deliverables/model.xlsx --evidence evidence/analysis-checkpoint.json --security TICKER --cutoff YYYY-MM-DD
python -B -X utf8 skills/report-layout/scripts/model_review.py begin STUDY --reviewer READER
```

Give the named fresh reader the workbook, specification and original pivotal evidence. They test source/period/unit/ownership definitions, driver assumptions, cash/financing and the valuation anchor, recording actual findings in the partial challenge handoff. `model_review.py check STUDY` checks completion and freshness; it does not perform the review. Use stable checkpoint/source paths rather than a living report draft that is routinely reformatted. Changes to reviewed model/evidence require affected rechecking.

For `writing`, pass `--research-mode regular-review` when only price/presentation changes reuse the existing operating model, and `--model-changed` when that review reconstructs it. The pre-writing stage permits at most two started model reviews, preserves prior packets, and requires evidence-backed dispositions of earlier blockers. These are separate from publication-reader attempts. A regular price-only review may reuse an eligible unchanged model checkpoint; set `modelChanged` when regular-review work actually reconstructs the model. Model review must match the material study's cutoff/security. Writing and publication preflight check this dependency. No production helper marks a substantive checkpoint passed.

## Sequence

1. Complete and calculate the supported model, valuation, decision and evidence checkpoint. Freeze the relevant paths with `publication_review.py writing STUDY --inputs model/spec.json evidence/research_record.md deliverables/brief.json`. Include the actual decision/valuation records when separate. The resulting `evidence/writing-packet.json` records hashes and a task, not completed work. Give a fresh writer that checkpoint, the short [writing standard](../../research-brief/references/natural-writing.md), layout instructions and access to original pivotal sources. Missing essential evidence returns to analysis.
2. Generate HTML from the calculated model. Full initiations include a model-linked summary of income, balance sheet and cash flow, using sector-appropriate rows, available historical periods and forecast periods. Use `Report.financial_summary(...)`; do not invent unavailable history. A bank or insurer needs its own meaningful statements and capital/distribution measures.
3. Call `report_layout.package(...)` as documented in the module. The first call prints draft PDFs, runs the existing integrity checks and creates a **partial** `evidence/draft-review.json`. It exits with `awaiting-review` and creates no release ZIP. The partial packet contains eight `not-run` checks; creating it does not perform a review.
4. Give a named fresh reader the exact PDFs, brief, calculated model and original pivotal evidence in that packet. Before work, the reader/host runs `publication_review.py begin STUDY --reviewer NAME` (`--review-mode human` for a human). This writes a start receipt bound to the immutable draft. Prefer a different model or a qualified human where available; a fresh instance of the same model shares blind spots. Read every page and compare decisive brief claims with the report through `coverage.brief-fidelity`: a firmer conclusion or lost material condition is a finding. Review conciseness, critical thinking, professional language, sharp writing, argument support and defensibility, plus source/financial basis and visual quality. Reproduce material calculations and complete comparable-definition/incremental-flow coverage. Record concrete findings in the existing strict `challenge` handoff. Mark complete only after doing the work. Reasonable forecast uncertainty remains labeled uncertainty; it need not block publication.
5. Resolve material defects through their owning analysis, then regenerate affected HTML/model outputs. Correct or cut an unsupported claim; add prose where analysis was missing rather than accumulating qualifications around the old claim. Rerun the study's package adapter with `revise=True`: it reprints, reruns every integrity check with the bindings passed now and freezes a new draft. `publication_review.py prepare STUDY --revise` does the same on the saved record and fails when the revision has made those bindings stale. The previous review is archived, the old release ZIP is removed and the publication status is invalidated before reprinting. Default budget: two started review attempts, retained across draft versions. If material findings remain after the budget, keep a draft and the unresolved findings; report what remains. Do not weaken checks or label continued self-review independent to obtain a ZIP.
6. When the review genuinely completes, run `publication_review.py check STUDY`, then `publication_review.py finalize STUDY`. Finalization validates and packages the **same reviewed PDF bytes**, without reprinting. Changed analytical inputs require an affected updated review. A narrowly verified presentation-only correction can use the confirmation path below; unrelated tests/evaluation changes do not change the pinned production rules. Recheck an existing release with `release_check.py STUDY`.

Commands use `python -B -X utf8 skills/report-layout/scripts/publication_review.py ACTION ...`. Chrome is required for printing; Node.js and the repository's installed dependencies validate the existing common challenge schema. Set `CHROME_PATH` or `NODE_BINARY` when host discovery needs help. Declare `timezone` in the release record or `RESEARCH_TIMEZONE` for the session (this workspace defaults to Asia/Singapore). A cutoff date includes available information in that local day, capped at actual production time or the explicitly declared synthetic clock, rather than UTC midnight. The reader declaration is auditable metadata, not authentication or proof of independence.

## Review packet and financial assertions

Before preparing the draft, synchronize the [decision checkpoint](decision-record.md) from the calculated model. `decisionRecord` defaults to `evidence/decision.json`; it is automatically frozen and fingerprinted. Missing/stale core values, model/spec hashes or declared trigger-text bindings block current publication. Build the decision before writing so a current report cannot coexist with an older machine-consumable result. The helper preserves qualitative judgments; the reader must verify whether they remain supported.

Use [general prose/range bindings](claim-support.md#feasible-bridges-and-actual-displayed-figures) for material figures beyond the three financial-assertion families. The checker compares actual span text and its declared transformation with bound calculations, including signs and range endpoints. Binding a number does not validate the surrounding causal claim. Explicitly test a feasible counterexample before accepting a claim that an aggregate estimate uniquely requires particular drivers.

The current wrapper has `schemaVersion: 1.2`, `researchMode`, `draftVersion`, `reviewer` (`id`, `mode: independent-agent|human`, `context: fresh`), `round`, `maxRounds`, `priorReview`, `priorRequirements`, `priorDispositions`, `reviewedFiles` (study-relative paths to SHA256), `skillsFingerprint`, `snapshot`, `evaluation`, `valuationBasis`, `coverage`, `financialAssertions`, `claimAssertions` and the existing `handoff`. Pass `researchMode: initiation|regular-review|earnings-update|catalyst-update` to the package adapter from routing; it is not an extra user prompt. Use `prepare` to construct the packet. The wrapper remains 1.2; new lifecycle requirements are pinned production-rule behavior, not a silent relabeling of older packets. The reviewer replaces unperformed checks with actual results; no production helper fills in passing reviews.

**Drafts versus attempts.** `draftVersion` advances on every preparation. `round` is the prospective review attempt, advancing only after a named reader starts the preceding attempt. Preparing/reprinting an unreviewed packet does not spend a review attempt; `begin` does, including failed or interrupted work. Repeating `begin` for the same reader/draft is idempotent. The default remains two attempts. Preserved start receipts fix the budget across renamed packets and retain failed work; do not delete receipts or enlarge the budget to obtain a pass. New drafts preserve the preceding review by hash. `priorRequirements` retains earlier failed blocking checks and essential unknowns through intervening unreviewed drafts. Each needs a `priorDispositions` entry (`id`: the generated `draft-N/check-name` or `draft-N/unknown-M`, `status: resolved|disagreed`, `reason`, registered `sourceIds`). Carry/revalidate a supported resolution in the current review. A supported disagreement with a mistaken reviewer is legitimate; erasing a finding is not. These local files detect ordinary resets, not a hostile party rewriting all history.

Current preparation does not silently convert earlier review histories (including schema 1.0 and 1.1) or discount their earlier attempts. Use the archived-rule runner to continue or inspect the actual original version. Keep frozen historical outcomes with their original rule bytes; reuse eligible model/evidence components in a separately versioned study. Moving an old history to current rules requires an explicit migration preserving its actual attempts/findings; running the preserved rules does not require relabeling it as 1.2. Integrity-only historical inspection remains the explicitly labelled legacy mode below.

**Preservation before review.** Preparation copies every reviewed input into `evidence/review-snapshots/round-.../files/`, saves the release record and manifest, and archives the actual rule bytes in `rules.tar`. Build scripts and top-level build JSON are included; add other producer/dependency paths under the release record's `reviewInputs`. The next draft archives the prior review in its actual state, including an unperformed preparation or interrupted attempt. Read the snapshot when comparing versions. Never overwrite the first draft and attempt to recreate it afterward. The gate checks snapshot and live-file hashes; this detects drift, not a dishonest party rewriting every record. A changed live bundle requires using the study's pinned runner; it does not invalidate a review under its preserved version. Read-only preflight checks eligibility before reprinting or invalidating artifacts. PDFs are rendered and integrity-checked in staging before canonical PDF replacement. A refused command preserves the prior artifacts and budget. Accepted failed builds remain failed attempts, without claiming a new release. Snapshot content objects share unchanged bytes where hard links are supported, with a copy fallback; hashes still detect altered retained bytes.

**Evidence and uncertainty.** A claim of superiority needs compatible evidence for both sides, not just a strong number for the company. Missing relative evidence can require removing a comparison without forcing a worse forecast. Put reasoned forecast uncertainty in assumption/inference claims, scenarios and dated revision triggers. `criticalUnknowns` is only for unknowns that actually prevent a defensible release; every entry blocks finalization, regardless of a sentence calling it nonblocking. Do not clear a genuine blocker merely to obtain a pass.

**P/E economic basis.** Complete `valuationBasis` as `checked` with exactly three `cases` (`bear`, `base`, `bull`). Each declares `period`, `benchmarkPeriod`, `metricRef`, `multipleRef`, `targetRef`, optional `fxRef` and scenario `selector`, registered `sourceIds` and a `rationale`. All use the selected house forward period. The base references match the headline release bindings. Base `sensitivityPricing` lists each covered sensitivity's `id` and pricing `period`; reprice shocks on that same primary method. Use the [generic example](../assets/valuation-basis.example.json) for field structure, not a required business assumption. Other primary methods use `not-applicable` with a reason and empty cases; their appropriate financial-basis review remains required. A cross-period peer table can inform judgment, but multiplying CY peer P/E by CY EPS and dividing by NTM EPS to label the result an NTM multiple does not create an NTM economic anchor. The checker catches exact inverse-EPS cancellation; source relevance, other hidden dependencies and the quality of benchmark adjustments still require review.

**Synthetic test clock.** Ordinary production retains the real research cutoff, production and retrieval times. A host may predeclare `.research-evaluation.json` in a clean fixture workspace, or `evaluation` in its release record, with `{"mode":"synthetic-fixture","now":"2030-01-15T12:00:00Z","reason":"Fixed invented evidence-pack date"}`. This clock is only for synthetic research, never a live source or portfolio decision. Preparation copies it to the review wrapper, marks its fixture sources synthetic and still records actual `producedAt`/`retrievedAt`. Reviewers must mark newly added fixture sources synthetic too. Future-cutoff production without this explicit context fails; changing `producedAt` to the cutoff is not a workaround. The common handoff checker accepts `--fixture-clock ISO_TIMESTAMP --fixture-reason REASON` for this declared evaluation. The readiness API additionally requires `allowSynthetic: true`; it continues testing production time against the real `nowMs`.

For each of `cash-coverage`, `normalized-ratio` and `financing`, declare economic `applicability` separately from verification `status`. An applicable family needs `applicability: applicable`, `status: checked`, the exact unique `assertionIds` of its financial assertions, and nonempty `claimIds` linked to registered handoff claims. Missing model rows, unavailable inputs or absent display bindings leave an applicable claim unverified; they do not make it economically inapplicable. A generic calculation assertion can supplement the required definition-aware family check but cannot substitute for it. Narrow or remove an unsupported claim, or finish the appropriate check, without inventing data.

Genuine non-applicability uses `applicability: not-applicable`, `status: not-applicable`, a substantive `reason`, and empty `assertionIds` and `claimIds`; no assertions of that family may be hidden. Preparation initializes applicability as `undetermined` and status as `undecided`; these block release. The reader determines whether claims were omitted or misclassified. This separation does not infer economic applicability from a word search, prescribe an ownership haircut, or impose industrial cash measures on financial institutions. All assertions use logical model-cell references, include `id`, `kind`, `period`, `unit`, `rationale`, and bind material displayed outputs through `displays`. See the clean [synthetic assertion example](../assets/financial-assertions.example.json); replace all fictional cells and definitions.

- **Cash coverage:** `beforeOutflows`, `remainingOutflows`, `availableCash`, `distributions`, `coverage`, `accountingTreatment`. Remaining outflows are positive amounts not already deducted. Test cash after required obligations divided by distributions, while retaining separately labeled company-reported measures. Explain accounting classification to avoid subtracting leases twice. Do not force industrial FCF onto a financial institution.
- **Normalized ratio:** `baseValue`, `baseIncome`, `removedComponents` (paired `value`, `income`, `rationale`), `normalizedValue`, `normalizedIncome`, `ratio`, `basis` and optional `peerBases`. Basis states claim boundary, income definition, ownership, currency, scale, lease treatment and period convention. Strip related income with a removed asset; keep operating costs with the appropriate operating claim. Compare normalized peers on the same basis or retain only a labeled directional comparison. Do not strip operating liquidity from a bank as surplus cash.
- **Financing:** effective-dated `terms` with `source`, `locator`, `publishedAt`, `effectiveFrom`, `principal`, `contractualFx`, `conversionPrice`; `asOf`; bound `principal`, `contractualFx`, `conversionPrice`, `conversionShares`; and `scenarios` for bear, base and bull. Each scenario binds `target`, `baseShares`, `shares`, `profit`, `afterTaxAddback`, `eps`, with `conversionWeight` and `rationale`. An in-the-money scenario without conversion needs `nonConversionReason`. Crossing a conversion price does not compel holder exercise. Explain period weighting, debt/cash/put treatment and interest effects in the model and review. The arithmetic checker tests the supplied share/EPS bridge, not every possible financing contract.

**Sensitivity coverage:** `coverage.sensitivity` is `checked` with the `sensitivityIds` of every material published model sensitivity, each declared under `sensitivities` in the specification and reproducing through the full model, or `not-applicable` with a reason, for example when the decisive output is not EPS or another reviewed method tests it. The check confirms the listed IDs; the reviewer confirms that the list is complete.

**Payoff and inference:** review price movement and eligible cash receipts on the same dated horizon when describing an overall investor outcome; a cash yield alone is not that outcome. Dividends remain separate from the price-target rating. The [original payoff example](../assets/payoff-calculation.example.json) demonstrates a generic bound calculation, not a required return forecast. Date-matched comparisons test a claimed period change; historical levels alone do not establish its cause. Inspect drivers-before-detailed-valuation in a full initiation. These judgments remain substantive reader work, not automated prose certification.

**Claim support:** the wrapper's `claimAssertions` and `coverage.claim-support` address material set generalisations, evidence populations, ownership/access of cash metrics, and new numerical corrections proposed by reviewers. Read [claim support](claim-support.md) for bindings and limits. Reproduce replacement figures before prescribing them. A passing ledger does not validate broader unbound prose.

**Comparable definitions, incremental flows and the brief:** complete `coverage.comparisons` and `coverage.incremental-flows` with their typed assertion IDs or reasoned non-applicability. Earnings updates additionally account for material flow candidates with checked derivations or sourced explanations of unavailable/noncomparable data; initiation and catalyst work do not fabricate a prior forecast or quarter to fill the inventory. `coverage.brief-fidelity` is checked with decisive `items`, each identifying a recorded `claimId`, `reportLocation`, `briefLocation`, `qualification` and `assessment`. Keep material denominator, source-vintage, time, ownership and forecast-condition distinctions. The reader checks omitted candidates/claims and actual prose; a populated ledger alone does not establish completeness.

**NTM calculation modes:** use the [dated NTM guide](dated-ntm.md) for quarter/half/irregular-period coverage and changing shares, or retain a justified, labelled annual interpolation. Passing an implemented convention does not justify its economic selection.

Render critical outputs with `bound_value(id, calculated_value, period, unit, fmt)`, e.g. `bound_value('cash-cover', cover, 'FY2027E', 'x', lambda v: f'{v:.2f}x')`. Its span records raw value, period and unit. The matching display entry is `{"id":"cash-cover","ref":"Cash!H20","period":"FY2027E","unit":"x"}`. The checker compares both raw value and visible rounding. Other metrics need their own model references and substantive review; these three families are a starting scope, not a universal financial theorem.

`prose-number-inventory.json` is an advisory list of figures in rendered text. A nearby or identical workbook value does not establish the right metric, year or accounting basis. Unbound prose remains subject to review. Source facts normalized into a terms schedule can still be wrong; file existence and correct arithmetic cannot validate extraction or source truth.

## Bounded presentation confirmation

Material errors in any review dimension block release: clipped signs, misplaced year/value columns and illegible charts can be financial errors. All eight dimensions must be reviewed; the four analytical dimensions must pass. A genuinely cosmetic issue can remain explicitly nonblocking with its rationale. The reader decides materiality; a category name alone does not establish it.

`publication_review.py confirm STUDY` prepares one partial confirmation for the original reader when only editorial/presentation findings remain. It permits changes only to rendered HTML/PDF or semantically unchanged brief JSON, and checks visible content equivalence plus unchanged analytical/model/source/decision inputs. The original reader must actually inspect the corrected print and diff, then complete that confirmation handoff. The original substantive review, its failed finding and attempt receipt remain unchanged; the confirmation is retained and fingerprinted separately. It is not another independent review and does not reset the budget.

Changed earnings, cash, source data, numerical text, valuation or other analytical inputs require substantive review, even if the rating and primary method remain unchanged. One local confirmation cannot become an unlimited rewrite loop. Old failed studies cannot acquire this new prospective allowance by relabeling their archived rules.

## Supported target bridges

The primary method field supports P/E, P/B, dividend-yield, SOTP, NAV, residual-income, EV/EBITDA and EV/Sales. Company economics and the canonical decision rules choose the method; supporting a method in code does not prescribe it.

Explicit FX must be finite and positive; omit it only for a same-currency bridge. P/E, P/B and enterprise multiples require positive comparable metric bases and positive multiples. A yield target requires a positive required yield and nonnegative DPS; zero DPS is a valid no-distribution scenario, not permission to substitute a yield of one. For loss-making or negative-book businesses, select an economically supported alternative instead of multiplying two negative inputs into a positive target. Source and economic suitability still require review.

EV methods bind `enterpriseMetric`, `targetMultiple`, `netDebt`, `nonOperatingValue`, `minorityValue`, `shares` and optional `fx`, with matching period, unit and ownership definitions. Target equals `(multiple * enterprise metric - net debt + nonoperating value - minority value) / shares / fx`.

SOTP/NAV/residual-income declare `valuationParts`, each with unique `id`, `valueRef`, optional `ownershipRef` and a `rationale`, plus bound `shares` and optional `fx`. Values are signed owner-value components, such as operating parts, assets, obligations, book capital or explicitly modeled present values. The target sums those components and divides by shares/FX. A component cannot consume the target it purportedly verifies. Economic discounting, terminal assumptions, source relevance, claim boundaries and appropriate scenario pricing remain substantive model/review work; a target alias is not a parts bridge.

## Visual review and migration

Tables may split with repeated headers and intact rows; charts stay intact. Keep a debate in one normal-flow wrapper so its answer cannot overlap a repeated table header. Review page-end headings, gaps, clipped or colliding labels and readable type at the actual printed width. A large blank area can be justified by an intact chart or a long row; the approximate 15% guideline is diagnostic, not an automatic failure or an excuse to shrink type. Use a table for a small earnings bridge; a nonzero chart axis is optional and must be explicit and marked as truncated.

Existing builders must adopt the financial summary, applicable bindings and review workflow before making a new release. Historical studies are not automatically migrated. For an integrity-only historical inspection, `release_check.py STUDY --legacy` explicitly skips the new review requirement and reports `legacy-verified`, never a current reviewed release. Do not use that flag as a publication shortcut.

Deterministic tests establish that the supported path rejects tested missing/stale reviews and defined arithmetic errors. They do not establish review quality, execution on other paths or consistent research scores. Test those separately with fixed-evidence end-to-end trials across fresh runs, including valid counterexamples, missed material errors, false blocks and corrective interventions.
