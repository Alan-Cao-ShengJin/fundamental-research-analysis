You are the data-engineering lead for a global fundamental equity-research system.

Repository:
https://github.com/Alan-Cao-ShengJin/fundamental-research-analysis

Read AGENTS.md, then these files under docs/data-planning/2026-11-02/:
- README.md
- global_source_catalog.json

Goal
Turn these requirements into a practical, prioritized plan for reusable worldwide data pipelines that help analysts build stronger assumptions across twenty sectors. Start with general public/industry data and reusable public-disclosure collection. Proprietary company telemetry is outside the initial scope.

Geographic scope
Design for global markets from the start. Match observations to a company's customer, operating, production and input-cost exposure. Listing country is a separate attribute. Record actual country/product coverage and gaps; a provider marketed as global does not cover every metric, country, frequency or historical period. Regional adapters should extend the same schema.

Your work
1. Critically validate the catalogue. It contains 81 source families, not 81 mandatory integrations. Consolidate overlapping feeds and separate original publishers from redistributors, actual observations, modeled estimates and forecasts.
2. Propose the smallest useful first implementation. Prioritize cross-sector reuse: identity/security mapping, official disclosures, prices/FX/actions/calendars, macro/credit/labor, trade/production and commodity costs. Add sector modules according to research needs. Prefer public data and sufficient existing entitlements; identify optional licensed gaps separately.
3. For each selected source, produce a validation matrix with its exact official URL/dataset ID, fields, units, geography/population, frequency, release lag, history, revision behavior, access method, authentication, request limits, commercial/internal-use rights and expected acquisition/maintenance effort. Use small public samples where feasible. Label unverified claims and inaccessible data honestly; never treat a visible chart as proof of a usable historical API or bulk license.
4. Propose a storage/query design using the existing repository and actual scale requirements. Preserve immutable raw snapshots, normalized observations, entity mappings, release/revision vintages, parser/transformation versions, quality findings and source rights. Explain technology choices and tradeoffs before recommending infrastructure.
5. Refine the proposed observation contract into an implementable schema. Preserve native values plus normalized units, original-language evidence, stock/flow/average, nominal/real, seasonal adjustment, cumulative/standalone and gross/net/consolidation distinctions. Missing remains null with a reason. Keep source publication, known first availability, retrieval and forecast target dates separate.
6. Specify an initial vertical slice demonstrating source -> raw archive -> normalized observation -> reproducible as-of query -> research-facing output. Include a normal observation, missing value, delayed release, correction/restatement and a changed unit or definition. If genuine historical vintages are unavailable, label the limitation and archive going forward rather than inventing past availability.
7. Define the analyst handoff: traceable observations, coverage/quality reports and links to model/assumption identifiers. Analysts own exposure selection, causal calibration, pass-through/lag assumptions and forecasts. Do not automatically convert an industry growth rate into company revenue growth or set a forecast coefficient from a convenient correlation.
8. Provide implementation milestones, estimated effort, key tradeoffs, open questions and acceptance criteria. Distinguish proposed, sampled, validated and operational capabilities. Do not purchase subscriptions, activate recurring jobs or claim worldwide production coverage as part of a planning exercise.

Deliverables
- A prioritized source-validation matrix and explicit global coverage/gap matrix.
- An architecture proposal and implementable observation/entity/vintage schema.
- The smallest first vertical slice, with sample inputs/outputs or prototype retrieval where access permits, and reproducibility/quality tests.
- A phased backlog with effort, dependencies, ownership and measurable acceptance criteria.
- A short list of decisions needed from the research team.

Use the catalogue as a starting hypothesis. Challenge it where a better source, simpler design or narrower initial slice is justified. Keep sample credentials and entitled responses out of Git.
